## The village pipeline in 1.21.1 (verified from the client jar)

- Villages are `minecraft:jigsaw` structures: `data/minecraft/worldgen/structure/village_<style>.json` each declares `"biomes": "#minecraft:has_structure/village_<style>"`, `"start_pool": "minecraft:village/<style>/town_centers"`, `size: 6`, `terrain_adaptation: "beard_thin"`.
- All five styles are bundled in one `data/minecraft/worldgen/structure_set/villages.json` (`random_spread`, spacing 34, separation 8, salt 10387312).
- Pieces come from `worldgen/template_pool/village/<style>/{town_centers,streets,houses,terminators,decor,villagers,...}.json`, referencing NBT templates under `data/minecraft/structures/village/...`.
- **Villagers spawn from the separate `village/<style>/villagers` pools** (NBTs containing villager entities) — replacing only house templates produces empty villages.

## Phase 1 (done): villages in cherry groves — tag injection

One file in the mod: `src/main/resources/data/minecraft/tags/worldgen/biome/has_structure/village_plains.json`:

```json
{ "replace": false, "values": ["minecraft:cherry_grove"] }
```

Tags merge across all data packs by path, so `cherry_grove` joins vanilla's `plains` + `meadow` in the plains-village biome tag. Plains style was chosen as the aesthetic match (meadows are cherry groves' neighbor biome). No code, no overrides.

Alternatives considered and rejected (verified against neoforge-21.1.256): NeoForge `StructureModifier`s only wrap spawn overrides — cannot change structure biomes; biome modifiers cover features/carvers/spawns/climate only; a custom structure set would require overriding the vanilla `villages` set (mod-conflict-prone).

## Verification recipe (deterministic)

1. Create a **Single Biome** world with **Cherry Grove** (More World Options -> world type).
2. `/locate structure minecraft:village_plains` — every chunk is cherry grove, so a hit proves the structure now qualifies for the biome. The command names the structure, so a hit IS the precise check (not just "changes did something").
3. Villagers present confirm the full pipeline; they spawn from the vanilla plains `villagers` pool, unaffected by biome-tag changes.

## Phase 2 (done, evolved): config-gated cherry-material villages

The custom `siasworkshop:village_cherry` jigsaw path sketched below was NOT taken. Instead, vanilla plains pools are overridden with composed processor lists ending in `siasworkshop:cherryfy`, gated by the `cherryfyVillages` server config (default off) — full design, gotchas, and roll-out status in [cherryfy-villages](cherryfy-villages.md). The "do NOT override vanilla pools" warning stands: the override approach was accepted only because the feature is opt-in; the custom-structure path below remains the conflict-free alternative.

- Build a custom `siasworkshop:village_cherry` jigsaw structure (100% datapack JSON is possible: structure, own structure_set with own salt, template pools, processor lists) with template pools pointing at OUR NBT templates authored via structure blocks (48^3 limit per piece; link with jigsaw blocks) or Axiom.
- References: TelepathicGrunt/StructureTutorialMod (structure datagen), ChoiceTheorem's Overhauled Village and Repurposed Structures (proven material-themed village template packs).
- Pitfalls: match vanilla `projection` (houses/town centers `rigid`, streets/terminators `terrain_matching`); use `legacy_single_pool_element` like vanilla; remember the `villagers` pool; do NOT override vanilla pools (conflicts with other village mods); MCA Reborn is NOT a worldgen reference (its villages are runtime SavedData scanning player builds).
