## What it is
- Darkhax's general-purpose library mod ("code, frameworks, and utilities for other mods"); docs claim 42,000+ dependent projects. Powers Enchantment Descriptions, Botany Pots, Tips, Dark Utilities.
- Not a content mod — it's infrastructure other mods compile against. PRIORITY REFERENCE for siasworkshop.

## NeoForge 1.21.1 support
- Fully supported, actively maintained. Dedicated `1.21.1` branch: `gradle.properties` pins MC 1.21.1, NeoForge 21.1.209, Java 21, Parchment 1.21/2024.07.28, version range `[1.21.1,1.22)`.
- Latest published `bookshelf-neoforge-1.21.1` on Maven is 21.1.81 (repo metadata updated 2026-02-10).
- Multi-loader layout: `common/`, `neoforge/`, `fabric/` subprojects. No `forge/` dir on this branch (README's Forge line is stale). Newer branches (`26.1.1`, `26.1.2`, `26.2`, `26.3`) track newer MC versions (exact mapping unverified).

## Core API in a nutshell
All under `common/src/main/java/net/darkhax/bookshelf/common/api/`:
- `registry/` — `ContentProvider` (Darkhax's DeferredRegister replacement), `RegistryReference`, `RegistrationContext`, `adapters/` wrapping loader registries.
- `network/` — `IPacket`, `AbstractPacket`, `INetworkHandler`, `Destination`; wrapper over vanilla/NeoForge payload registration.
- `data/` — `codecs/` (incl. `EnumStreamCodec`, map/stream helpers), `conditions/` (custom JSON conditions), `ingredient/`, `loot/`, `enchantment/`, `BookshelfTags`, `ISidedRecipeManager`.
- `util/` — `CommandHelper`, `DataHelper`, `ExperienceHelper`, `TextHelper`, `MathsHelper`, `TickAccumulator`; `IPlatformHelper`/`IGameplayHelper`/`IRenderHelper` service interfaces.
- Also: `block/`, `item/`, `entity/`, `menu/`, `loot/`, `commands/`, `text/`, `annotation/`.
- Platform abstraction: `service/Services.java` (ServiceLoader) with impls in each loader module; `common/mixin/` for shared mixins.

## Who uses it / practices worth borrowing
- Users: Enchantment Descriptions, Botany Pots, Tips, Dark Utilities, ~42k projects per docs page.
- `registry/ContentProvider.java` — single registration entry point per mod, loader-agnostic.
- `service/Services.java` + per-module `impl/` — SPI-based platform abstraction worth imitating for any multiloader ambitions.
- `network/` — minimal typed-packet layer.
- `data/codecs/`, `data/conditions/` — reusable codec/condition toolkit for data-driven JSON.
- Build: `buildSrc` convention plugins (`multiloader-loader`), gradle.properties-driven metadata, ModDevGradle + Parchment block in `neoforge/build.gradle` (near-identical toolchain to siasworkshop), CurseGradle + Minotaur publish tasks in the same file.

## Watch-outs
- Version numbers track NeoForge (21.1.x), not semver — check Maven for latest rather than trusting the README snippet.
- API-first design: most logic lives in loader-neutral `common`; copy-pasting a class into a NeoForge-only mod may drag `Services` indirection with it.
- Branch-per-MC-version: always read the `1.21.1` branch; `main`/default and newer branches target other MC versions.
- LGPL obligations if borrowing source (not just depending).
- The `forge` artifact line in the README is stale for this branch.
