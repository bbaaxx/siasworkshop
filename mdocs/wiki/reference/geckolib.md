## What it is
- GeckoLib is the de-facto animation/entity-model library for modded Minecraft: keyframe-based 3D animations, 30+ easings, concurrent animation stacking, sound/particle/event keyframes, math-based animations.
- Models/animations are data-driven JSON (Blockbench "GeckoLib" plugin exports `.geo.json` / `.animation.json` into `assets/<modid>/{geo,animations,textures}`).
- One codebase ships for Forge, Fabric, Quilt, and NeoForge from a multi-loader repo.

## Core API in a nutshell
All under `software.bernie.geckolib` in `common/src/main/java/software/bernie/geckolib/`:
- `animatable/` — implement `GeoAnimatable`, or subtypes `GeoEntity`, `GeoItem`, `GeoBlockEntity`, `GeoReplacedEntity`; `SingletonGeoAnimatable` for server-driven sync.
- `animation/` — `AnimationController` state machines, `AnimationState` per-frame context, `RawAnimation` builders, `EasingType`.
- `model/` — `GeoModel` subclass pointing at your JSON assets.
- `renderer/` — `GeoEntityRenderer`, `GeoItemRenderer`, `GeoArmorRenderer`, `GeoBlockRenderer`, `GeoReplacedEntityRenderer`, plus `layer/` render layers.
- `cache/` + `loading/` + `resource/` — JSON model/animation loading and reload listeners; `network/` — sync packets; `service/` — platform abstraction.

## Who uses it / practices worth borrowing
- Used by Mowzie's Mobs, Ars Nouveau, Creeper Overhaul, ChaosAwakens, many more (wiki keeps a "Geckolib Powered Mods" list).
- Multi-loader `common/` + `neoforge/` module split sharing one `accesstransformer.cfg` (`common/src/main/resources/META-INF/accesstransformer.cfg`).
- Convention plugins + version catalog in `buildSrc/` and `gradle/libs.versions.toml`.
- Data-driven asset pipeline decoupled from code (`loading/`, `cache/`, `resource/`).
- `SingletonGeoAnimatable` + `network/` pattern for animation state sync without entity data params.
