## What it is
- Team CoFH's mod ecosystem — the Thermal series and shared libraries. Org (44 repos): `CoFHCore` (base lib mod), `ThermalCore` (mod id `thermal`, shared Thermal framework), content mods `ThermalFoundation`, `ThermalExpansion`, `ThermalDynamics`, `ThermalInnovation`, `ThermalCultivation`, `ThermalIntegration`, `ThermalLocomotion`, plus side mods (`RedstoneArsenal`, `Ensorcellation`, `ArchersParadox`).
- Core + expansion split: CoFH Core is required by everything; Thermal Core is required by every Thermal mod (shared items, creative tabs, augment framework); each expansion adds one domain (Foundation = ores/materials/tools, Expansion = machines/dynamos, Dynamics = conduits, Innovation = gadgets, Cultivation = farming).

## Architecture and repo layout
- One repo per mod, same skeleton: `<Mod>.java` entrypoint, `init/registries` (static `register()` helpers wrapping NeoForge `DeferredRegister`/`DeferredHolder`), `common/block|block/entity|inventory`, `client` (screens), `compat` (JEI), `init/data` (datagen).
- Layered packages: `cofh.lib` (CoFHCore: api/util/init), `cofh.core` (config, network, GUI framework, mixins), `cofh.thermal.core` + `cofh.thermal.lib` (ThermalCore: RegistrationHelper, ThermalIDs, augment rules, machine/dynamo base classes).
- Machine recipes/tags fully JSON datagen-driven; energy = Forge Energy (FE, descends from Redstone Flux). Server configs per-world; client/common split.

## Practices worth borrowing
- Registration discipline: `ThermalCore/src/main/java/cofh/thermal/core/util/RegistrationHelper.java`, consumed by `ThermalExpansion/src/main/java/cofh/thermal/expansion/init/registries/TExpBlocks.java`.
- Augment (machine-upgrade) system: `ThermalCore/src/main/java/cofh/thermal/lib/util/ThermalAugmentRules.java` and `BlockItemAugmentable`.
- Tiered machine/dynamo block-entity bases: `cofh/thermal/lib/common/block/entity` (e.g. `MachineBlockEntity`).
- Per-expansion `compat/` + `init/data` package split; centralized changelogs in the `CoFH/Version` repo.

## Watch-outs
- Copying is legally throttled (see License); renaming variables counts as copying.
- Legacy trap: default branches are 1.20.x — Java 17, NeoGradle (not ModDevGradle), pre-1.21 capability/networking APIs.
- Heavy indirection across four layers; cross-repo version ranges (`cofh_core [11.0.2,11.1.0)`) make partial upgrades brittle.
- README is license-only; official wiki/docs are stale (1.12-era).
