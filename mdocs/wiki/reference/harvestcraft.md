## What it is
- Pam's HarvestCraft (MatrexsVigil / Pamela Collins): classic farming/cooking mega-mod — 80+ crops, fruit trees, gardens, bees/fish, hundreds of foods with tool-based recipes. Final HC1 repo targets MC 1.12.2, Forge 14.23.5.2768, ForgeGradle 2.3, MCP snapshot mappings, Java 8 (from `build.gradle` in repo).
- Successor: Pam's HarvestCraft 2 (CurseForge user `pamharvestcraft`) — a reboot split into four modules: Food Core, Crops, Trees, Food Extended.

## Status on MC 1.21.1 / NeoForge
- Upstream `MatrexsVigil/harvestcraft`: frozen at 1.12.2, last activity ~2018–2019. No 1.21.1/NeoForge anything — inspiration only, code not directly portable.
- Maintained successor — Pam's HarvestCraft 2: official, closed-distribution mod. NeoForge 1.21.1 builds confirmed for all modules (e.g., `pamhc2foodcore-1.21.1-1.0.4`, Aug 2025; `pamhc2foodextended-NEOFORGE-1.21.1-1.0.0`, Feb 2025). Also ships Forge builds for 1.19.2–1.20.4. No official public source repo — releases via CurseForge/Modrinth only. (`github.com/NegotiatorAdapt34/pams-harvestcraft-2` is an unofficial prebuilt-JAR mirror, not source.)

## Architecture and repo layout
- Single module, package root `com.pam.harvestcraft` (`src/main/java/...`), organized by concern: `blocks/`, `item/`, `tileentities/`, `worldgen/`, `gui/`, `events/`, `config/`, `loottables/`, `proxy/` (ClientProxy/CommonProxy), `addons/`, `misc/`; entry `HarvestCraft.java`, `Reference.java`.
- Pre-registry-refactor style: static item/block lists initialized in `HarvestCraftBlocks`/`HarvestCraftItems`-style classes, worldgen hooks via Forge events, config-driven feature toggles, JSON recipes/loot under `src/main/resources`.
- Legacy Forge toolchain (FG 2.3, `minecraft { version = ... }` block, `deobfJar`/`reobfJar` tasks).

## Practices worth borrowing
- `worldgen/` — garden/bush scatter generation across biomes (the HC2 "right-click harvest, replant stage" crop model).
- `tileentities/` + `gui/` — simple one-slot "machine" blocks (grinder, pot, skillet) as pattern for low-TE-cost food stations.
- HC2's tool-in-recipe + tag-based generic recipes ("any fruit/vegetable in a correctly tagged mod") — very 1.21-datapack-friendly.
- HC2's four-module split (core/crops/trees/extended) as a study in mod modularization.
- `events/` + `config/` — lightweight hook layer keeping game logic out of main class.

## Watch-outs
- ARR license — no code or texture borrowing, ever, without written permission.
- HC1 code uses 1.12-era APIs (registry events, capabilities, old worldgen) — nearly nothing ports mechanically to NeoForge 1.21.1.
- HC2 has no public source; only decompiled JARs exist (license forbids non-educational decompile).
- HC2 requires the four modules in specific combinations (Food Extended needs Crops + Trees).
