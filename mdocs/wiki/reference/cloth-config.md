## What it is
- Client-sided config-screen library, the de-facto standard for in-game config GUIs. Two layers: a fluent `ConfigBuilder` API for hand-built screens, and optional annotation-driven "AutoConfig" (`@Config`/`@ConfigEntry` classes + pluggable Gson/Jankson/TOML/YAML serializers). By shedaniel (REI author).

## Core API in a nutshell
- Entry point: `me.shedaniel.clothconfig2.api.ConfigBuilder.create()` → `setParentScreen`/`setTitle` → `getOrCreateCategory` → `entryBuilder().startIntSlider/startBooleanToggle/startColorField/...` → `build()` returns a `Screen`; `setSavingRunnable` persists.
- Key types: `common/.../api/ConfigBuilder.java`, `ConfigEntryBuilder.java`, `AbstractConfigListEntry.java`, `Requirement.java`; screens in `gui/ClothConfigScreen.java`, `GlobalizedClothConfigScreen.java`; ~25 ready entries in `gui/entries/` (sliders, dropdowns, keycodes, color picker, nested/subcategory lists).
- AutoConfig: `common/.../autoconfig/` — `AutoConfig.java`, `serializer/`, `gui/registry/GuiRegistry.java` for custom field providers/transformers.

## Who uses it / practices worth borrowing
- Ubiquitous on Fabric, common on NeoForge; study it as the ecosystem reference.
- Fluent builder design: `api/ConfigEntryBuilder.java` + `impl/builders/*Builder.java`.
- Entry (data/error state) vs widget (rendering/scroll) split: `gui/entries/` vs `gui/widget/DynamicSmoothScrollingEntryListWidget.java`.
- Annotation-config + serializer abstraction in `autoconfig/` — good model if siasworkshop wants data-driven config.
- Near-zero loader code: `neoforge/` holds only a demo + `UtilsImpl` — everything lives in `common` (`settings.gradle` includes common/fabric/forge/neoforge).
- Usage examples as demo classes: `ClothConfigDemo.java`, `ClothConfigForgeDemo.java`.

## Watch-outs
- GitBook wiki is stale (covers <= v11 / 1.20.x); README points to the GitHub wiki. Default branch is `v8` (MC 1.19.1) — always read the branch matching your MC version (`v15`).
- Client-only: no networking or server config sync; roll your own if needed.
- Its build is Architectury Loom + Architectury plugin, not ModDevGradle — borrow architecture, not build scripts.
- No automatic screen registration on NeoForge (no ModMenu equivalent): you must open the built screen from your own keybind/button.
- Shadows/relocates jankson, toml4j, snakeyaml — serializer deps are self-contained.
