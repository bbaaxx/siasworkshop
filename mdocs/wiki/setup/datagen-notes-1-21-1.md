## Loot tables (the piece that changed most in 1.21)

Verified against `build/moddev/artifacts/neoforge-21.1.256.jar` via `javap` (signatures below are exact for our toolchain):

- `LootTableProvider` constructor is 4-arg: `(PackOutput, Set<ResourceKey<LootTable>>, List<SubProviderEntry>, CompletableFuture<HolderLookup.Provider>)` — the registry future (from `GatherDataEvent#getLookupProvider()`) is passed here, not resolved by hand.
- `LootTableProvider.SubProviderEntry` takes a `Function<HolderLookup.Provider, LootTableSubProvider>` — so a loot-provider class whose constructor takes `HolderLookup.Provider` can be referenced directly as a constructor method ref: `new LootTableProvider.SubProviderEntry(ModBlockLootTables::new, LootContextParamSets.BLOCK)`. No `.join()`/`.get()` on the future needed.
- `BlockLootSubProvider` constructor: `(Set<Item>, FeatureFlagSet, HolderLookup.Provider)`. Subclasses still override the no-arg `generate()` and `getKnownBlocks()`.
- `GatherDataEvent#getLookupProvider()` returns `CompletableFuture<HolderLookup.Provider>`, not the provider itself.

## Blockstates and item models

- `BlockStateProvider.simpleBlockWithItem(Block, ModelFile)` emits both the blockstate and the block-item model in one call; `models().cubeAll(name, texture)` builds the block model. `mcLoc(...)` points textures at vanilla assets — the current placeholder art borrows `minecraft:block/iron_block` and `minecraft:item/apple` so no custom PNGs are needed yet.
- `ItemModelProvider.withExistingParent(name, parent).texture(...)` for simple generated items.

## Wiring and gotchas

- Register the gather listener from the mod constructor: `modEventBus.addListener(ModDataGenerators::gatherData)` — it only fires during `runData`.
- Gate providers with `event.includeClient()` / `event.includeServer()`; output lands in `src/generated/resources/` (already a resource source dir in `build.gradle`).
- `.cache` files under `src/generated/resources/` are gitignored by the MDK `.gitignore`; the generated JSON itself is committed (Ender IO does the same).
- When a class moves packages, package-private members break silently at compile time (Config.SPEC had to become public after moving to `config/`).
- Verifying mappings signatures: `javap -classpath build/moddev/artifacts/neoforge-<version>.jar <fqcn>` beats guessing from memory or older tutorials.
