## gradlew loses its execute bit

Extracting the MDK zip (or copying the template folder) drops the execute permission on `gradlew`. Eclipse Buildship is unaffected — it invokes the wrapper differently — but CLI runs fail with `./gradlew: Permission denied`. Fix: `chmod +x gradlew`.

## Let Eclipse sync warm the cache

Importing the project via Buildship (Gradle sync) downloads Gradle, Minecraft, NeoForge, and the Parchment mappings. A later CLI `./gradlew runClient` then boots in minutes. Avoid running an Eclipse sync and a CLI build at the same time — they contend on `.gradle/` locks and the shared dependency cache.

## Expected WARN lines on the first client run

The stock MDK example content ships no model or texture files, so the log shows `missing model for variant: 'siasworkshop:example_block#'` and `Unable to load model: 'siasworkshop:item/example_item'` (FileNotFoundException). These are WARN-level and expected — the block and item still register, appear in their creative tabs, and place fine; they only render with the missing-texture checkerboard until models are added under `src/main/resources/assets/siasworkshop/`.

## Local tooling note: mdocs Kimi plugin patch

The managed Kimi plugin manifest (`~/.kimi-code/plugins/managed/mdocs/kimi.plugin.json`) is locally patched to launch the MCP server via an absolute path, working around a spawn-cwd bug. Reinstalling or updating the plugin reverts the patch — the upstream fix is tracked at bbaaxx/harness-mdocs#10. Symptom if reverted: `MCP server "plugin-mdocs:mdocs" failed: MCP error -32000: Connection closed`. The `mdocs` CLI fallback keeps working regardless (`./node_modules/.bin/mdocs`).

## Creative tab bar paginates — missing tabs are often on page 2

In 1.21.1 the creative inventory tab bar paginates once the tab count exceeds one page (arrows + `1 / 2` indicator at the top). A custom tab placed late in the order (e.g., `withTabsBefore(CreativeModeTabs.COMBAT)`) lands on **page 2**. Symptom looks exactly like "the mod's tab didn't register": search finds the items, but the tab isn't visible. Before debugging registration, click the `>` arrow. Tab placement is controlled by `withTabsBefore`/`withTabsAfter` in the tab builder.

## Convention: mod tab = full catalog, vanilla tabs = selective placement

The stock MDK sample splits content confusingly: the example item goes into the custom tab's `displayItems`, while the example block item is injected into vanilla Building Blocks via a `BuildCreativeModeTabContentsEvent` listener — so the block never appears next to the item. The convention this project follows (see `SiasWorkshopCreativeTabs`): list **all** of the mod's content in its own tab, and treat vanilla-tab placement as an optional, per-content decision in the `addCreative` listener.
